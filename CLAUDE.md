# ggrace519/.github

Shared reusable GitHub Actions workflows. This repo is public so that private repos can call them.

- Branch model: `develop` is the default and integration branch. `main` is promoted through a PR, and releases are tagged on main. Releases also move the major tag `v1`. Release tags (`vX.Y.Z`) are protected by the `protect-release-tags` ruleset, which only admins can bypass; the major tag `v1` is excluded from it so that `self-release.yml` can move it. Known callers pin a release commit SHA (`@<sha> # vX.Y.Z`), not `@v1`. A new release does not reach them until each caller's pin is bumped. To find callers, scan every repo's `.github/workflows` across ggrace519, 519lab and tric-it2750. Code search misses private repos.
- Lint: `actionlint` (CI: `.github/workflows/lint.yml`). On ubuntu runners actionlint also runs shellcheck over `run:` scripts, so check scripts locally with `uvx --from shellcheck-py shellcheck -s bash` when shellcheck is not installed.
- `release.yml` is the reusable changelog-driven tag-and-release workflow; `self-release.yml` runs it for this repo on every push to `main`, and as a `dry-run` check on the promotion pull request. That check fails unless `[Unreleased]` was rolled into a dated `## [X.Y.Z]` section; `version.yml` does the roll. If a ruleset ever covers `v1` again, the release is still created, the run fails at the tag move, and a re-run after fixing the ruleset repairs it. The `github-actions` app cannot be a bypass actor on a user-owned repo.
- `version.yml` is the reusable changelog roll-up: it computes the next version from the `[Unreleased]` entries and commits the rolled changelog to `develop` as `github-actions[bot]`. `self-promote.yml` runs it and then `promote.yml` after lint passes on a develop push, and runs it as a `dry-run` preview on pull requests into `develop`. Do not roll the changelog by hand in a feature branch; add entries under `[Unreleased]` only. After a roll-up, local `develop` is behind: pull before branching. The rationale is ADR-001 in `DECISIONS.md`.
- The workflow logic lives in `run:` blocks and has no test suite in the repo. To test a change, extract the `run:` script and drive it against throwaway git repos with `gh` stubbed for the API calls.
- `promote.yml` came from homelab-swarm's inline script. Keep the logic in sync here only. homelab-swarm now calls this workflow.
